# Maintaining this site

This site is [**The Digital Mailroom**](https://mailroom-inc.gitbook.io/the-digital-mailroom/), published with [GitBook Git Sync](https://gitbook.com/docs/getting-started/git-sync) from [Exios66/mailroom-documentation](https://github.com/Exios66/mailroom-documentation) (this repository). The Git Sync **Project directory is the repository root**, so `README.md` is the site landing page (the `mailroom-docs` space is mounted at path `/`). A merge to `main` replaces that home.

The **Changelog** section is not a page in this repository: it is generated from the `llm-mailroom` repository's `CHANGELOG.md` — never hand-edit it. In that repository, run `PYTHONPATH=src python src/scripts/sync_gitbook_changelog.py` to regenerate it; `--check` is the guard.

## Connecting the GitBook site (one-time)

1. In GitBook, open the site's space (the `mailroom-docs` space, titled "Mailroom Inc. Docs").
2. Open the space's **Configure** menu, choose **GitHub Sync**, and install the GitBook GitHub app on `Exios66/mailroom-documentation`.
3. Pick the `main` branch and set the **Project directory** to the repository root (`.`).
4. Choose **GitHub to GitBook** for the first sync so the repository content is imported rather than overwritten.

After that, a merge to `main` updates the site. Edits made in the GitBook editor come back as commits.

Mermaid diagrams render on GitHub; in GitBook they need the Mermaid integration enabled on the space, otherwise they show as code blocks.

## `path` vs `directory` (this is the usual mix-up)

The Project directory, `content.directory`, and `path` are three different knobs. Only `path` is a URL slug:

| Knob                                        | File                 | Meaning                                                        | Correct value here                                                                                             |
| ------------------------------------------- | -------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Git Sync **Project directory** (GitBook UI) | —                    | Where GitBook looks for `gitbook-docs.yaml`                    | **the repository root (`.`)**. `gitbook-docs.yaml` sits at the repo root.                                       |
| `content.directory`                         | `gitbook-docs.yaml`  | Git folder the space reads, relative to the Project directory  | `./` (the repository root)                                                                                      |
| `path`                                      | `gitbook-docs.yaml`  | URL after the site slug                                        | `/` (site home). `path: docs` would publish at `…/the-digital-mailroom/docs/`                                   |
| space `key`                                 | `gitbook-docs.yaml`  | Stable identifier for the `mailroom-docs` space                | `mailroom-docs` — **never change it**                                                                           |

`path` is a URL slug, not a folder name. With the Project directory at the repository root, `content.directory: ./` is correct. There is no `docs/` subfolder in this repository.

GitBook also replaces the markdown H1 with the `SUMMARY.md` link title. Keep that link as `* [LLM-MAILROOM](README.md)` so the GitBook page header reads **LLM-MAILROOM** and matches the `# LLM-MAILROOM` heading in `README.md` (the previous `* [Welcome](README.md)` title is why the live home used to read **Welcome**).

GitBook's published favicon is the site icon in **Customize** ([icons, colors, and themes](https://gitbook.com/docs/manage-your-site/customization/icons-colors-and-themes)). Git Sync cannot set it: `gitbook-docs.yaml` has no favicon field. Upload `.gitbook/assets/hoot-icon.png` (Hermes, the pixel owl).

## Rules for editing

* **Link, don't copy.** Each repository's own README and `docs/` stay canonical. A guide here summarizes what a newcomer needs to orient, then links to the source. This follows the llm-mailroom rule that `docs/` content is never duplicated.
* **Every new page goes in `SUMMARY.md`.** A page that is not listed is not published. Operator recipes that belong on this site (Docker compose matrix, Modal + vLLM) live at the repository root in their section folder and are listed here — `deploy/README.md` is a file index, not a GitBook page. Sandbox run reports and visuals are nested under the [local-mailroom-sandbox](../repository-guides/repos/local-mailroom-sandbox/) guide. The canonical corpus has its own top-level section ([Mailroom dataset](../mailroom-dataset/mailroom-dataset.md)); static PNGs stay on `Exios66/Mailroom-Corpus-EDA` `main` (`raw.githubusercontent.com`) and the live dashboard / Plotly charts / Hub viewer are iframes from `exios66.github.io/Mailroom-Corpus-EDA`.
* **Use relative links between pages on this site** (`repos/llm-mailroom.md`, `../architecture.md`) and full GitHub URLs for anything in another repository.
* **Date facts that drift.** Versions, pins and counts carry an "as of" date; when a release moves them, update [Overview](../start-here/overview.md) and the affected guide.
* **Link to `llm-mailroom` pipeline paths, don't relocate them.** References such as `pipeline-reference-llm-mailroom/...` and GitHub URLs under `Exios66/llm-mailroom/...` describe the pipeline and stay as they are.
* **Keep the GitHub wiki separate.** The `llm-mailroom` repository's own `docs/wiki/` remains wiki-only and is not mirrored on this site.
* **Keep the GitBook Changelog generated.** After editing `llm-mailroom`'s `CHANGELOG.md`, run `PYTHONPATH=src python src/scripts/sync_gitbook_changelog.py` in that repository. The GitBook onboarding placeholders in that section are gone; do not put them back.
